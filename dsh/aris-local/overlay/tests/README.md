# Offline ARIS migration tests

Run `node --test tests/*.test.mjs` from this package with an isolated HOME and cleared credential environment after building DSH `0.2.0-rc.2`. `DSH_CHECKOUT` is mandatory: there is no default/live checkout fallback. DSH/Cordis imports resolve only inside the selected checkout; manifest tests require the actual target version and all three exact peers. Temporary roots are private package siblings under `test-work`, removed in teardown. Run `python3 -B tests/helpers-offline.py` with pytest installed for six pinned upstream helper suites and local resource/grant/concurrency regressions; it clears the environment, isolates HOME/TMPDIR and blocks socket operations and external process execution. No upstream installers run.

Coverage: runtime-only activation, ARIS_REPO ownership/disposal, the real Cordis post-execute waterfall, original reviewer content and metadata, read-only RPC registration, real SkillRegistry/filesystem-provider isolation across host/Standard/Research scopes and descendants, all 83 upstream bodies/resources, reparenting and unload invalidation. Bundle tests use the rc.2 YAML parser and patch engine, with an inert static full-preset comparison and the standalone `../standard-local.patch.yml` compaction override. The browser module factory test exercises the new per-session slot injection. The Python bridge process accepts initialize/tools-list only with an isolated HOME and nonexistent CODEX_BIN.

These are focused unit, registry, and patch-composition checks. They do not boot a full Web profile, load a migrated session, create a real subagent, contact an authenticated reviewer, or prove a live browser rendering. The parent assembler must verify those separate integration surfaces. No live profile/config, credential, or user conversation file is read by this suite.
